# אג'נט להכנת פגישות ולזיכרון פגישות

## הסבר קצר

**הבעיה:** בארגונים מתקיימות פגישות רבות עם אותם אנשים, אבל לא תמיד על אותם נושאים. בין פגישה לפגישה מידע הולך לאיבוד, משימות נשכחות, ולפעמים דנים שוב בנושא שכבר הוכרע.

**למה בחרתי בה:** זו בעיה יומיומית שכל צוות מכיר. מצד שני, היא דורשת שיקול דעת אמיתי: להחליט אם פגישה היא המשך של נושא קודם, אם להציג מידע ישן, ומתי לעצור ולשאול. מתוכנית רגילה אי אפשר לצפות לזה.

**מה האג'נט עושה:** הוא מקבל מטרה. לפני פגישה המטרה היא להכין תדריך, ואחרי פגישה המטרה היא לנתח את הסיכום ולעדכן את הזיכרון. בכל צעד האג'נט בוחן את המידע שכבר אסף ובוחר את הפעולה הבאה: לחפש נושאים קודמים, לבדוק משתתפים, לשלוף החלטות ומשימות, לשאול את המשתמש או לשמור. אחרי כל פעולה הוא בודק את התוצאה, והיא קובעת את הצעד הבא. האג'נט עוצר כשהמטרה הושגה, כשנדרשת הבהרה שלא התקבלה, כשקובץ הזיכרון פגום, או כשהגיע למגבלת הצעדים. מודל השפה (Gemini) רק מחליט. את כל הפעולות, כמו שליפה, אימות ושמירה, מבצע הקוד, והקוד גם בודק שההחלטה מתאימה לנתונים.

## איך זה עונה על דרישות המבדק

| דרישה | איפה זה בקוד |
|---|---|
| קבלת מטרה | `goal`: ‏`prepare_meeting` או `summarize_meeting` (`main.py`, `AgentState`) |
| קבלת החלטות | `GeminiBrain.decide` בוחר את הכלי הבא לפי המטרה והמידע שנאסף. `RuleBrain` הוא גיבוי (`agent.py`) |
| שימוש בכלים | 11 כלים ב-`tools.py`, למשל `search_topics`, `get_open_tasks`, `save_meeting` |
| בחינת התוצאה | כל תוצאה נרשמת ונבדקת, והיא קובעת את הצעד הבא. החלטה לא תקינה נדחית (`Agent.run`) |
| תנאי סיום | `finish` מתקבל רק כשהמטרה באמת הושגה. יש גם עצירה בשגיאה ומגבלה של 12 צעדים (`_finish_allowed`, `MAX_STEPS`) |

בכל צעד מודפסת שורת יומן כזו:

```json
{"step": 3, "goal": "prepare_meeting", "decision": "retrieve_related_meeting",
 "reason": "התאמה חזקה ל-T001", "tool_used": "set_context", "result_checked": true,
 "next_action": "check_participants", "status": "ok", "result": "הקשר: continuation → T001", "brain": "gemini"}
```

### ההפרדה בין המודל לקוד

- **Gemini** מחליט איזה כלי להפעיל ועם אילו ארגומנטים, ומחלץ החלטות ומשימות מסיכום חופשי.
- **הקוד:**
  - מאמת שהכלי קיים ושהארגומנטים תקינים.
  - מסרב לקשר פגישה לנושא שהחיפוש לא מצא.
  - מסרב לסיים לפני שהמידע הדרוש נאסף.
  - דוחה פריטים שהמודל "המציא" ושלא מופיעים בסיכום.
  - שומר בצורה אטומית עם גיבוי, וקורא את הקובץ מחדש כדי לאמת את השמירה.
- **בלי מפתח, או כש-Gemini לא זמין,** האג'נט עובר אוטומטית למוח מבוסס כללים. הפלט מציין בבירור באיזה מצב הוא רץ.

## הכלים

| כלי | תפקיד |
|---|---|
| `load_memory` | טוען ומאמת את `memory.json`. אם הקובץ פגום, האג'נט עוצר בלי לכתוב |
| `search_topics` | מחפש נושאים קודמים לפי מילות מפתח, עם סובלנות לאותיות שימוש (ה, ו, ב...) |
| `set_context` | רושם את ההחלטה על ההקשר: המשך, קשר עקיף, נושא חדש או לא ברור |
| `check_participants` | מחזיר תפקידים, ומזהה משתתפים חדשים או חסרים לעומת הפגישה הקודמת |
| `get_topic_history` | שולף פגישות והחלטות קודמות של נושא |
| `get_open_tasks` | שולף משימות פתוחות ומסמן איחור רק כשתאריך היעד חלף |
| `ask_user` | שואל שאלת הבהרה. האפשרויות נבנות מהנתונים ולא מהמודל |
| `extract_summary` | מחלץ החלטות, משימות ועדכונים מסיכום הפגישה, ומאמת אותם מול הטקסט |
| `check_conflicts` | מזהה החלטה חדשה שסותרת החלטה פעילה באותו נושא |
| `save_meeting` | שומר את הפגישה. סתירה שלא אושרה לא דורסת את ההחלטה הקודמת |
| `verify_saved` | קורא את הקובץ מחדש ומוודא שהשמירה הצליחה |

## התרחישים

| # | תרחיש | מה האג'נט מחליט |
|---|---|---|
| 1 | המשך ישיר של נושא קודם | שולף את ההחלטות והמשימות של הנושא ומציג נושא קשור כ"טעון אימות" |
| 2 | נושא חדש עם אותם משתתפים | לא מציג החלטות מנושאים אחרים רק כי המשתתפים זהים |
| 3 | קשר עקיף לנושא קודם | מציג את המידע הקודם ומסמן במפורש שהקשר טעון אימות |
| 4 | הקשר לא ברור | לא מנחש: שואל את המשתמש וממשיך לפי התשובה, ועוצר אם אין תשובה |
| 5 | משימה פתוחה או באיחור | מציג אחראי, תאריך יעד והצעה לברר סטטוס, בלי להניח שהמשימה לא בוצעה |
| 6 | החלטה חדשה שסותרת החלטה קודמת | מציג את שתי ההחלטות ומבקש אישור. לא דורס אוטומטית |
| 7 | שינוי במשתתפים | מזהה מי חדש ומי חסר, ומתאים את השאלות לתפקידים |
| 8 | קובץ פגום או שמירה שנכשלה | עוצר, לא כותב כלום, ולא מדווח הצלחה כוזבת |

## הדגמה – ריצה אמיתית

צילומי המסך הבאים צולמו מריצה אמיתית של האג'נט בדפדפן, עם נושא שהוקלד ידנית ולא נלקח מתרחישי ההדגמה.

**הקלט:** פגישה בנושא "החלטה לגבי העובד החדש האם להכניס אותו למשרד", עם יוסי לוי (Backend) ורחל גרין (UI/UX).

![הגדרת הריצה בדפדפן](docs/run_input.png)

**הפלט:** האג'נט חיפש בזיכרון ולא מצא נושא קודם מתאים, ולכן החליט שזה **נושא חדש** (תרחיש 2). הוא זיהה ששני המשתתפים כבר נפגשו בעבר בנושא "שיפור תהליך ההזמנה", אבל **לא הציג** את ההחלטות משם, כי הן לא קשורות לנושא הנוכחי. השאלות לכל משתתף הותאמו לנושא חדש.

![הפלט של האג'נט](docs/run_output.png)

הפלט המלא של כל תרחישי ההדגמה בשורת הפקודה, כולל יומן ההחלטות של כל צעד, נמצא בקובץ [`demo_output.txt`](demo_output.txt).

## התקנה

נדרש Python 3.10 ומעלה.

**Windows (PowerShell):**
```powershell
cd hadarAgent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

**Mac / Linux:**
```bash
cd hadarAgent
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

אחר כך פותחים את `.env` ומכניסים את המפתח מ-[Google AI Studio](https://aistudio.google.com/apikey):
```
GEMINI_API_KEY=המפתח-שלך
```
המפתח נקרא ממשתנה סביבה ואף פעם לא נשמר בקוד. הקובץ `.env` מופיע ב-`.gitignore` ולא יעלה ל-GitHub.

**מגבלת קצב:** המפתח החינמי של Gemini מוגבל במספר הקריאות לדקה וליום. לכן הקוד:
- ממתין לפחות 6 שניות בין קריאות. את המרווח קובעים ב-`GEMINI_MIN_INTERVAL_SEC`.
- בשגיאת 429 ממתין כמה ש-Gemini מבקש, ומנסה שוב.
- אם Gemini עדיין לא זמין, עובר למצב גיבוי, ובשורת היומן מופיע קוד השגיאה המדויק.

אפשר להחליף מודל דרך `GEMINI_MODEL` ב-`.env`.

## הרצה

### בדפדפן (הדרך הנוחה)
```bash
python web.py
```
הדפדפן נפתח אוטומטית בכתובת http://localhost:8000. אם הוא לא נפתח, פותחים את הכתובת ידנית.

**בדף אפשר:**
- לבחור תרחיש הדגמה או למלא נושא, משתתפים ותאריך בעצמכם.
- לראות כל צעד של האג'נט בזמן אמת: איזו החלטה התקבלה, איזה כלי הופעל, מה התוצאה ומה הצעד הבא.
- לענות על שאלות ההבהרה של האג'נט ישירות בדף.
- להציג או לאפס את הזיכרון. הדפדפן עובד על עותק בתיקייה `runs/`, כך ש-`memory.json` המקורי לא משתנה.

עוצרים את השרת עם `Ctrl+C` בטרמינל.

![צילום מסך של ממשק הדפדפן](docs/screenshot.png)

### בשורת הפקודה

**הדגמה של כל התרחישים** (הפלט נשמר גם לקובץ):
```bash
python main.py demo --out demo_output.txt
```
ההדגמה עובדת על עותק של הזיכרון בתיקייה `runs/`, כך ש-`memory.json` המקורי לא משתנה.

**הכנה לפגישה:**
```bash
python main.py prepare --topic "המשך שיפור תהליך ההזמנה" --participants P001,P002,P003 --date 2026-10-27
```

**סיכום אחרי פגישה ועדכון הזיכרון:**
```bash
python main.py summarize --topic "המשך שיפור תהליך ההזמנה" --participants P001,P002,P004 --summary-file samples/summary_order_meeting.txt --date 2026-10-27
```
כשהאג'נט צריך הבהרה, הוא מציג אפשרויות ממוספרות ומחכה לבחירה.

**הרצה בלי Gemini:** מוסיפים `--offline` לכל אחת מהפקודות.

**בדיקות אוטומטיות** (16 בדיקות, רצות בלי מפתח):
```bash
python -m pytest -q
```

> טיפ: ב-Windows מומלץ להריץ ב-Windows Terminal או בטרמינל של VS Code כדי שהעברית תוצג כראוי. הקובץ `demo_output.txt` נשמר בקידוד UTF-8.

## מבנה הפרויקט

```
main.py            נקודת כניסה: prepare / summarize / demo
web.py             ממשק דפדפן (שרת מקומי, ספרייה סטנדרטית בלבד)
web/index.html     הדף שמוצג בדפדפן
docs/              צילומי מסך של ריצות אמיתיות
agent.py           לולאת האג'נט, Gemini, מוח הגיבוי ובניית הפלט
tools.py           הכלים והאימות של הארגומנטים
memory.py          קריאה, אימות מבנה ושמירה אטומית עם גיבוי
memory.json        זיכרון לדוגמה: participants, topics, meetings
samples/           סיכום פגישה לדוגמה וקובץ זיכרון פגום לתרחיש 8
tests/             בדיקות pytest
demo_output.txt    פלט אמיתי של ריצת ההדגמה
```

## מגבלות ושיפורים אפשריים

- החיפוש מבוסס מילות מפתח ולא חיפוש סמנטי, ולכן נושא שמנוסח במילים אחרות לגמרי לא יזוהה. שיפור אפשרי הוא embeddings של Gemini.
- במצב הכללים (בלי מפתח) צריך לכתוב את סיכום הפגישה בתבנית שורות (`החלטה [נושא]: ...`, `משימה: שם | תיאור | תאריך`). עם Gemini אפשר לתת טקסט חופשי.
- קובץ JSON מתאים למשתמש אחד. כתיבות מקבילות ממספר תהליכים דורשות בסיס נתונים.
